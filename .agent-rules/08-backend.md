# Backend: минимальный, только при необходимости

Сначала выясни, нужен ли backend вообще. Для статического лендинга с текстом, изображениями и ссылками предпочитай статическую сборку и хостинг без сервера. Не создавай API, базу данных, авторизацию и фоновые процессы «на будущее».

Backend добавляй только для реальных требований: обработка заявок, интеграция с CRM, личный кабинет, динамические данные или защищённые операции. Выбирай уже используемый стек проекта; не добавляй отдельный сервис, если достаточно serverless-функции или одного небольшого API.

Держи API компактным: только нужные маршруты, строгая проверка входных данных, понятные коды ответов, ограничение размера запросов и обработка ошибок. Секреты храни только в переменных окружения на сервере. Никогда не отправляй приватные ключи, токены и пароли в браузер или репозиторий.

Для форм проверяй данные на сервере, добавляй защиту от спама и ограничение частоты запросов. Не доверяй клиентской валидации. Разрешай CORS только нужным origin. Используй HTTPS на production.

Базу данных подключай только если данные действительно нужно хранить. Выбирай минимальную схему, индексы под реальные запросы и параметризованные запросы/ORM. Не храни лишние персональные данные. Не создавай микросервисы для простого сайта. Документируй переменные окружения и способ запуска.
