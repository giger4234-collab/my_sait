# Frontend: архитектура и качество кода

Сначала используй существующий стек и соглашения проекта. Не мигрируй на другой фреймворк ради предпочтений. Для нового проекта выбирай минимальный стек, подходящий задаче; обычный лендинг не обязан быть SPA или иметь сложное состояние.

Разделяй страницу на небольшие компоненты по смыслу: Header, Hero, секции, формы и Footer. Не создавай один гигантский компонент. Общие элементы выноси в переиспользуемые компоненты только при реальном повторении. Храни дизайн-токены в CSS-переменных, избегай дублирования и конфликтующих глобальных стилей.

Используй TypeScript там, где он уже предусмотрен или уместен. Избегай any без причины, не маскируй ошибки типизации. Не добавляй библиотеку, если задачу можно решить небольшим количеством нативного кода. Не дублируй зависимости и не меняй lock-файл вручную.

Не оставляй console.log, мёртвый код, неиспользуемые импорты, фиктивные ссылки и обработчики-заглушки. Не храни секреты во frontend. Проверяй обработку ошибок, пустые состояния и отправку форм. Не меняй существующее поведение без согласования. Поддерживай читаемую структуру, понятные имена и предсказуемые компоненты.
